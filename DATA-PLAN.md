## Papercraft engine v2 (2026-11-22 fix & upgrade)
- The brief for this edit: replace the box-based conversion with a shape-preserving system — predefined faceted meshes per character, the SAME mesh driving the 3D preview and the unfolded print net, real assembly validation, QC statuses (Draft / Needs Review / Validated / Production Ready) where Production Ready additionally requires a tested physical prototype, an admin Papercraft Template Manager, and the dinosaur (name BABA) as acceptance test.
- Implementation (all original code, no external geometry library — none is installable on this surface): `client/src/lib/papercraft.ts` builds indexed triangle/quad meshes per component (lathe gores for rounded bodies/heads/snouts/tails, triangular prisms for spikes/fins/roofs, box strips, flat appliqué panels), unfolds each component's fold-strips by exact trilateration from the 3D edge lengths, generates glue tabs and numbered joins from the real cut edges, classifies folds mountain/valley from the 3D dihedral, shelf-packs pieces onto A4/A3 sheets, and numerically validates coverage, edge-length match, overlaps, page fit, stability (center of mass vs support hull), silhouette IoU vs the artwork, region mapping, nameplate fit, and instruction coverage.
- Dino 2D regions were split so the snout and feet are independently colorable (`regionFallbacks`: snout→head, feet→legs keep older saved projects consistent). Rocket and house were rebuilt on the same engine first; a follow-up pass (same day, after the audit flagged the remaining cube nets against brief §4/§5) converted the other 14 catalog characters too — every template now builds shape-preserving parts (lathe balls/tubes/cones mirroring its previous 3D model's coordinates, prism fins/wings/flags, box bodies for vehicles/buildings, flat appliqué windows/doors/patches) and unfolds its net from that same mesh. The old artwork-on-a-cube `blockNet` is gone entirely. Stability fixes found by the validator during conversion: rabbit/bear/cat feet were flattened and elongated so their contact ring carries the center of mass; the airplane gained a ventral tail fin as a stand; the astronaut's concave star patch became a flat appliqué because a concave prism cannot unfold without self-overlap.
- QC state is server data: `template_qc` (status, prototype flag, checks flag, scale %, tab depth mm, name offset mm) + `template_versions` audit rows (migration 0003). The updateTemplateQc action refuses Production Ready without both passed checks and a tested prototype.
- Silhouette-check framing fix (2026-11-22, full-catalog pass): `silhouetteIou` originally fit the artwork by its whole viewBox (including empty page margins and the name-label zone) while fitting the model by its own bbox, so loosely framed pages (car, planet, butterfly) scored 25–39% for framing rather than shape. The check now fits the artwork by the union bbox of its coloring regions (`artworkBounds`, paths sampled) — the same normalization the model side already used; the 42% threshold is unchanged. After the fix the catalog scores 44–88% in an independent re-implementation of the same math.
- Admin production PDFs (A4/A3, QC header, per customer project) are generated in the Parent Dashboard's Template Manager; the customer Print Studio keeps its existing at-home PDF (an original product feature) and now applies the manager's saved adjustments.

## Paper Pillow print model (2026-11-22, replaces the mesh net as the default print format)
- The brief for this edit: the user found the mesh papercraft net too difficult for children aged 2–6 and their parents (244 numbered joins for the dinosaur) and selected the "bantal kertas" (paper pillow) option exactly as presented: `the character is built from only 3–5 pieces: the FRONT PANEL is the child's exact colored artwork (its silhouette is 100% identical because it is the artwork itself), a BACK PANEL, and a connecting GUSSET STRIP around its edge that gives it thickness. Cut along the character's outline, glue the edges, done in about 10 minutes. It stands with a foldable base.`
- Implementation (all original code): `client/src/lib/pillow.ts` rasterizes the union of a template's coloring regions, traces the silhouette on the corner lattice (directed-edge boundary tracing, Douglas–Peucker simplification, one Chaikin smoothing pass — pure functions unit-tested on synthetic masks), and builds the net from that traced outline: front panel = the artwork itself (regions + details + freehand strokes, clipped to the outline in both the SVG preview and the PDF via a real clip path), back panel = mirrored outline in the largest region's color with the child's name, gusset strip = exactly the outline's perimeter long (two printed parts, one numbered join, pale fold-back glue tabs whose depth is the Template Manager's tab-depth setting), stand = a U-channel strip whose front flap carries the nameplate. Scale is capped by page fit AND by the perimeter fitting two strips, which is what keeps every character at ≤5 pieces.
- The mesh engine (`papercraft.ts`, `buildNet`, `analyzeCraft`) is untouched and remains available in the Print Studio as "3D Paper Toy · Advanced"; the standee is unchanged. The Print Studio default is now Paper Pillow. The Template Manager validates the PILLOW (`analyzePillow`: measured artwork↔outline overlap ≥93%, piece count ≤5, gusset length vs perimeter ≤0.5 mm, page fit, layout gaps, region coverage, name fit, stand stability, instruction coverage) and its admin production PDFs are pillow PDFs (A4/A3, QC header). The Production Ready gate is unchanged: automated checks AND a tested physical prototype, enforced in UI and server action.
- The 3D Magic Studio preview still renders the mesh model (a preserved feature); its compare caption now says the advanced print format is unfolded from that mesh, since the default print is the pillow.

## Long-term data behavior
- **Refresh policy**: No scheduled refresh; content is static code. Projects are user-created records read fresh from the DB on every view.
- **Growth**: One `projects` row per saved artwork (region colors + freehand strokes stored as JSON), one `settings` row for the configurable brand name. Users create/delete their own projects from My Creations / Parent Dashboard.
- **Ordering**: Projects listed newest-updated first.
- **Time semantics**: created_at/updated_at are creation instants rendered viewer-local; no event-time reasoning.
